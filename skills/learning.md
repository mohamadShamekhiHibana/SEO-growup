# Skill: یادگیری از نتایج (هفتگی)
هدف: تبدیل نتیجه اقدام‌های قبلی به تصمیم بعدی؛ بدون خودفریبی آماری.
1. `python3 scripts/fetch_gsc.py` (شیت GSC را دوباره می‌گیرد) → `python3 agents/analytics/snapshot.py` → `python3 agents/learning/review.py`.
2. برای هر `experiments_due`: مقدار فعلی معیار را با «مبنا» مقایسه کن. اگر نمونه کوچک است (هشدار review.py) بنویس «بی‌نتیجه/دیرتر دوباره» و `cli exp close` نزن مگر تغییر روشن باشد.
3. بنویس: چه چیزی تغییر کرد، چه چیزی احتمالاً علتش بود، چه چیزی نمی‌توان فهمید. هر نتیجه فقط با شاهد عددی؛ علّیت قطعی ادعا نکن.
4. صف تأیید: `cli stats` را ببین؛ نوع پیشنهادی که مدام رد می‌شود → دلیلش را حدس نزن، به کاربر بپرس و skill مربوط را اصلاح پیشنهاد بده.
5. فقط یافته‌های معتبر را با `cli learn "<موضوع>" "<بینش>" "<شاهد>"` ثبت کن. سفارش‌های لغوشده فعلی تستی‌اند.
6. هر اقدام جدید که اثرش قابل‌سنجش است (تغییر meta/عنوان، انتشار مقاله، کمپین) را با `cli exp add --what ... --hypothesis ... --metric ... --baseline ... --days 14` ثبت کن.
7. خروجی: `data/reports/learning/<تاریخ-شمسی-شنبه>.md` شامل: «نتایج»، «آزمایش‌های در جریان»، «پیشنهاد ۳ اقدام هفته بعد» (هرکدام با ایجنت مسئول)، «چیزهایی که نمی‌دانیم».
اصل: اگر داده کافی نیست، «داده کافی نیست» بنویس و چه داده‌ای لازم است (مثلاً export جدید GSC).
